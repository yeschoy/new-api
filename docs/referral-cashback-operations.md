# 邀请充值返现运维说明

## 上线顺序

1. 先部署数据库迁移和后端，确认 `cashback_order_contexts`、`cashback_rewards`、`cashback_device_links` 已创建。
2. 保持邀请人、被邀请人两个方向均关闭。
3. 在系统设置的 **Billing & Payment → Referral Cashback** 中配置单笔及 24 小时额度上限、T+N 和关联阈值。
4. 确认支付合规声明后，再按方向启用活动。
5. 使用新建在线充值订单验证记录生成、逐笔审核、到期结算和审计日志。首次启用前创建的订单不会补发。

## 结算与停用

- 返现记录必须同时满足人工审核通过、到达 `支付成功时间 + N×24 小时` 且没有当前硬阻断，才会由 `cashback_settlement` 系统任务发放到受益人的主额度。
- 关闭方向开关只停止后续支付成功订单的新计提；已有冻结记录仍按创建时快照处理。
- 如需紧急停止新计提，请关闭两个方向。不要删除返现记录或直接改写用户额度。
- 系统任务失败、对账异常、开放欠额及高风险聚集可在 `/cashback` 管理页查看。

## 退款、拒付和争议

首期**不接入支付渠道的自动退款、拒付或争议回调**。管理员必须在 `/cashback` 的返现详情中逐笔执行“记录支付异常”，并填写理由及可选凭证引用。

异常处置顺序固定为：

1. 取消尚未发放的双方返现，或从双方主额度追回已发放返现；
2. 再按累计退款比例冲正充值用户的原实际到账额度；
3. 余额不足部分分别记录为返现欠额或本金欠额，并阻断相关账号后续返现；
4. 欠额只能通过独立的管理员处置操作解决，解决不会恢复已取消奖励。

任何部分退款都会撤销该订单的全部返现，但充值本金只按累计退款比例冲正。管理员提交的是 0–10000 基点的**累计比例**；比例只能单调增加，重复提交同一异常和比例不会再次扣减。

## 会计边界

返现发放后直接混入 `quota`，系统不在日常消费时跟踪逐笔资金来源。异常处理采用“先取消/追回返现，再冲正本金”的确定性会计约定，不应解释为恢复了真实历史消费来源。

## 审计与隐私

配置修改、审核、异常处置、欠额解决以及完整 IP/设备详情读取均写入管理员审计日志。浏览器在登录、注册和在线充值下单时通过 `X-Device-Signal` 发送版本化信号；服务端只保存二次散列，且该信号只能作为关联风险证据。设备信号缺失或非法时，服务端使用仅限该用户的隔离锚点保留首次/最近 IP，该锚点不参与“同设备多账号”统计。缺失设备信号不会阻断正常充值，单一 IP 或设备命中也不会自动拒绝。
