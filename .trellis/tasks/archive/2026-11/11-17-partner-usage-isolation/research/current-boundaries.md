## 1. Current event flow and the meaningful scope decision

- `model/log.go:100` (`createLog`) ensures a request ID and writes **all supplied Log types** to `LOG_DB` through the Log model. Do NOT blindly route every Log by user membership: that would move top-up/system/security/refund events not included in this feature.
- `model/log.go:279` (`RecordErrorLog`) creates type=5, quota=0 with user/model/channel/request metadata. It does not require a selected subscription/billing source. This is a separate writer from settled consumption.
- `model/log.go:340` (`RecordConsumeLog`) creates type=2 and then feeds `LogQuotaData` when enabled. Zero-quota consumption is possible and still meaningful request history. `model/log.go:427` (`RecordTaskBillingLog`) is a context-free task writer; inspect actual supported Tenant task funding before declaring it irrelevant.
- `service/relay_error.go:76-97` writes channel failures with existing ErrorLogEnabled / IsRecordErrorLog suppression. Several auth/pre-consume failures are deliberately not written (`relaykit/types/error.go:392,413`; service billing pre-consume). An error may precede final funding selection. Do not invent failed-request billing/subscription IDs or force all suppressed/auth failures into new usage logs.
- `service/text_quota.go:531` records settled text usage through RecordConsumeLog. Final planning enumerated audio/websocket (`service/quota.go:250,389`), task submit/deltas (`service/task_billing.go:81,286,365`), legacy MJ (`relay/mjproxy_handler.go:290,672`) and charged violation fees (`service/violation_fee.go:150`); see `contract-decisions.md` for distinctions and the unchanged unsupported-Tenant-path boundary.
- `service/billing_session.go:397` forces Tenant members to subscription_only using immutable membership; ordinary subscription users also exist. **billing_source=subscription alone is not a Tenant classifier.**

**User-confirmed choice (next planning reply, “好”):** route all currently loggable authenticated Tenant model-call outcomes (success/zero consumption + failures) to the dedicated table so a failed then successful retry stays in one diagnostic surface. Preserve existing log/error-suppression switches and unknown subscription IDs; do not add a general request/body audit system. This scope confirmation is not final-plan or implementation approval.

## 2. Authoritative ownership and persistence placement

- `model/partner_tenant.go:48` stores unique `PartnerTenantAccount.UserId`, TenantId, TokenId, status and identity source. Both `external` (H5) and `subscription_key` identities are Tenant identities. Membership does not vanish because a merchant/account is disabled or naturally expires.
- `model/partner_tenant.go:31,84` caches only bool membership for one minute and publishes true on post-provision commit (`:280`). It cannot provide tenant_id/name/account_id for new log rows or user-list columns; any richer safe-owner cache must preserve invalidation/commit timing and not introduce stale negative ownership during provisioning.
- Capture validated server-side ownership at request time where possible; immutable snapshot in new rows prevents renamed merchant/group, disabled resources or later lookups from changing history. No username-prefix/group matching; no body/query-supplied ownership; no bearer/hash/seed lookup in log formatting.
- `LOG_DB` can equal DB or be separate. `model/main.go:236-247` sets LOG_DB=DB then migrates audits in the shared case; `:443-453` handles separate LOG_DB migrations. New-table migration must be wired into BOTH paths, not merely broad main DB AutoMigrate. No cross-DB SQL joins.
- `model/main.go:487` explicitly creates ClickHouse `logs` and implements TTL outside GORM. Keep current shared-driver support; a new logs table requires deliberate ClickHouse DDL/projection/cleanup treatment, not an accidental unsupported AutoMigrate. PostgreSQL is the acceptance priority (`.trellis/spec/backend/database-guidelines.md`).
- New log persistence must not fall back into default logs or dual-write silently on outage. Existing log persistence is best-effort and outside billing transactions; new failure policy must preserve paid/quota truth and disclose event-loss risk, not pretend cross-DB atomicity. No outbox is approved.

## 3. Read consumers and avoiding accidental claims of global isolation

- `model/log.go:530` admin list and `:738` top statistics read logs; SumUsedQuota unconditionally selects consume rows and sums quota, without a billing-source predicate. `controller/log.go:GetLogsStat/GetLogsSelfStat` exposes this; `web/src/features/usage-logs/components/common-logs-stats.tsx:69-93` formats that quota. Physical single-write separation naturally excludes new dedicated rows.
- `model/log.go:595,620` self list/request outcomes and `model/log_summary.go:35-39` per-user daily summary read **logs only**. `controller/log.go:77,114` scope them to authenticated user ID; `:231` obtains token_id from auth for key-specific recent logs (`model/log.go:144`). Moving writers changes those views. User has now explicitly confirmed (“好” to the own-user/API Key continuity question) preserving existing ownership-scoped read continuity, including each existing reader's authorization and redaction; single-write storage and no new login/merchant roles remain unchanged. Compatibility must include the existing self export alongside list/stat/outcomes/summary/token-recent reads, not only what the UI first renders. `model/log_outcome.go:10` picks one outcome per request but consumption sums and request deduplication are distinct operations. Do not count every retry attempt as an independent final success.
- `model/log.go:144` token recent logs, list/search/export (`:715`), CountOldLog/DeleteOldLogBatch (`:823+`) are further readers/cleaners. Existing default export must not unexpectedly union the new table. No new export system was requested.
- `RecordConsumeLog` still calls `LogQuotaData`. `model/usedata.go:40,102,129` keeps independent hour-bucketed counters in DB `quota_data` (Count/Quota/TokenUsed, etc.). Separating logs does **not** automatically isolate overall dashboard accounting or change users.used_quota/channel counters. User subsequently confirmed (“好” to the explicit dashboard question) that global homepage/dashboard totals continue including Tenant use while the admin default usage-log page/top stat excludes new dedicated rows. Preserve existing whole-site aggregation once; no global dashboard split is requested. Personal LogSummary and own-token continuity are now independently user-confirmed; physical separation must not make these authorized readers lose new history.
- User explicitly confirmed the historical transition (“好” to keeping old logs at the original entry and isolating new logs): default page retains pre-cutover rows and historical statistics, dedicated page starts with new rows; no administrator backfill/union or destructive history hiding by mutable ownership joins. This does not restrict the separately approved ownership-scoped personal union. Cutover is operationally when each writer is upgraded; mixed writers can split data, requiring coordinated rollout/explicit scope notice. A rolling deployment is not a magically atomic global timestamp.

## 5. User classification is a separate identity system from Partner OAuth

- `model/user.go:425,460` GetAllUsers/SearchUsers obtain count and paginated rows; existing partner_client_id filter at `:495-496` selects **PartnerAccount**, not PartnerTenantAccount.
- `controller/user.go:395-412` DTO enriches only PartnerClientId/PartnerClientName with PartnerAccountOwners. `:435` passes the old partner filter.
- `web/src/features/users/components/users-table.tsx:96,112-124,159-192` registers partner URL state and queries OAuth client options. `users-columns.tsx` and `components/__tests__/partner-column.test.tsx` already preserve this legacy integration. Keep those fields/filters; add a distinct Tenant classification/owner projection.
- Proposed category semantics: merchant=EXISTS Tenant account relation; ordinary=NOT EXISTS Tenant relation; all=no category predicate. Thus unrelated Partner OAuth/server users remain non-Tenant in this new classifier and keep their old partner labels. Disabled/expired accounts and visible soft-deleted users whose account mapping still exists remain attributable; they cannot silently become ordinary merely due status filtering. Recovery after physical removal of the mapping is not part of this feature.
- Both list and count must share category/tenant predicates before pagination; batch owner enrichment after pagination avoids N+1. Same owner primitive/semantics feeds logs and users. Canonical positive string tenant IDs avoid JS precision problems.

## 6. CNY quota projection without rewriting billing

- `model/partner_tenant_subscription_key.go:395-417` independent query DTO has nested quota decimal-string amounts and APIKey; `:422-485` computes quota under the authorized locked snapshot with strict active/terminal/unlimited semantics. Do not change those raw fields or re-query secrets outside locks for display conversion.
- `controller/partner_tenant.go:171-235` H5 merchant quota is a **numeric legacy DTO**, not the new string contract. `:240` catalog is also a legacy plan DTO. Additive amount fields can preserve both types and make total quota understandable before purchase; exact public field placement belongs to the CNY child design.
- `service/partner_oauth_payment.go:34-44` display conversion follows configured display kind (CNY/custom/USD); `:56-63` uses exact decimal but rounds six places. A mandated CNY projection cannot blindly call this preference-driven helper when the site switches to USD/custom/TOKENS. Use an explicitly CNY conversion based on quota_per_unit and USDExchangeRate, independent of current UI preference.
- Use exact int64 -> decimal arithmetic; no float round trips for quota. Return strings, stable currency=CNY and safe conversion metadata. Unlimited total/remaining should be unambiguously non-finite (existing flag authoritative), not falsely presented as zero; expired/cancelled usable remaining remains zero, historical display remains nonspendable. Invalid conversion config must not fabricate CNY values or block billing truth.
- The 15000000 -> 30 CNY example is conditional on the prior public configuration (500000 quota/unit, CNY rate 1), not a hardcoded universal conversion.
