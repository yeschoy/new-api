# 充值页返现预览

## Goal

充值人在选择金额时，同时看见适用活动返现规则和该账号本次预计奖励，而不会误以为预估就是已到账。

## Background / Confirmed Facts

- `web/src/features/wallet/components/recharge-form-card.tsx` 的在线充值有预设/自定义金额、多个支付方式和独立 Creem 产品卡，但尚无返现信息。
- `controller/topup.go:24` 的 `/api/user/topup/info` 不含用户活动资格/次数/返现预估；实际奖励在支付成功时经活动、限额、次数与资金状态计算。
- 比例与每满 100 固定额的计算均以充值面额为基数，而非折扣实付额；用户明确要求**活动规则和个性化预计金额两者都展示**。

## Requirements

1. 登录用户选金额时展示充值人方向当前活动规则（百分比或每满 100 固定额）以及按本次所选面额、该用户活动次数、单笔/24 小时剩余额度估算的奖励；预设和自定义输入同步更新。不同支付面额（如 Creem 产品）不套用普通充值金额的结果。
2. 关闭活动、次数耗尽、额度归零、不足最低返现门槛或预览不可用时，不展示伪造的正额奖励；清晰说明适用/不适用及“预计，实际以支付成功时的资格与结算为准”。
3. 预览只读、不预占权益；服务端仍依据真实支付验签、活动、欠额、额度等条件决定最终计提/授信。用户 API 不暴露其他用户、IP/设备、风控快照和管理员敏感配置。
4. 复用已有充值 UI/金额格式，七语 i18n；不影响现有在线付款及兑换码入口。

## Acceptance Criteria

- [ ] 选择预设/自定义金额或 Creem 产品时，适用活动的规则和该用户对应预计奖励在充值页可见，切换输入不出现过期金额。
- [ ] 无活动、无资格、零额和预览失败各有可信的用户提示；实际奖励仍由支付成功路径决定，预估不承诺最终到账。
- [ ] 金额/基数与后端计提规则一致，用户 API 信息最小化，七语、加载/错误与界面行为有聚焦回归。

## Out of Scope

- 为邀请人向充值用户预告其本人奖励；预占活动次数或额度；用估算替换支付完成的真实计提；公开后台风险材料。
