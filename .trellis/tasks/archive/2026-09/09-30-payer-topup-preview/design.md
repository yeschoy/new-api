# 技术设计：充值页返现预览

## 边界与 API

- 现有 `/api/user/topup/info` 仅提供一般支付配置；为登录用户提供**只读、有界、不可授信**的个性化预览接口。入参为在线充值所选面额以及必要的支付方式/Creem 产品标识；与下单请求保持可验证的整数范围和面额转换。响应只提供当前活动是否适用、可公开的返现规则、当前预估额度、无资格/零额的安全原因、计算依据时间/活动 ID 等非敏感字段；不返回其他用户数据、IP/设备、风控阈值或管理员全局设置。
- 预览按当前配置和活动窗口、方向开关、当前用户活动正额使用次数、24 小时已占用额度、单笔上限、选定充值面额与 `rate`/`per_hundred` 原服务端公式计算。该路径和支付成功计提应复用稳定计算/封顶逻辑，而不是前端复制算法或用支付折扣计算奖励；Creem 产品基数是产品 quota/面额，不从其标价反推。
- 预览是读取时刻的一次估算，不能预占活动次数、额度或修改任何返现记录。下单与支付成功仍各自复核资格，可能发生竞态、活动提前结束、支付失败、异常/欠额；不可对用户承诺资金到账或预计审核结果。

## 前端与行为

- 在 `RechargeFormCard` 已有金额区域组合项目的提示/状态组件，不重复实现表单或弹窗。预设和自定义金额更新时请求服务端预览，过期响应不得覆盖新金额；请求失败时展示“暂不可预估”而非零返现或正额承诺。
- 同一展示附活动规则与预计返现；无活动/关闭/次数耗尽/额度归零时呈现有区分的状态。若启用独立的 Creem 产品卡，对产品选择在付款确认处展示对应产品预览，防止标准金额的预估套用到不同支付面额。
- 普通数额/货币格式复用 `@/lib/format` 与 `@/lib/currency`，界面语言进入 Intl 先 `toIntlLocale`；七语文本通过 `i18n-translate` 脚本流程生成。充值页面仅展示充值人奖励，邀请人奖励不在用户预览中作为其本人权益宣传。

## 兼容与验证

- 原 API 与支付请求兼容；新增响应只供预览且不成为授信输入。若 DB 读取预览需要新增查询，保证边界、索引和三种 SQL 方言；避免无界扫描或把管理端鉴权接口公开给普通用户。
- 服务器不可用/配置读取失败时付款行为不受预览影响；回滚前端可隐藏预览，回滚接口不改变既有资金记录。
