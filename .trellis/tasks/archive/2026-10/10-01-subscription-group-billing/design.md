# 设计：按实际分组选择订阅资金来源

## 边界与数据契约

- `SubscriptionPlan` 增加持久化的单个 `ApplicableGroup string`（JSON `applicable_group`，数据库 `varchar(64) NOT NULL DEFAULT ''`；空表示不限）。不写入 `UserSubscription` 快照：按用户要求，管理员编辑后对活跃订阅的新请求即时生效。`UpgradeGroup` 不变。
- 管理员创建/更新均校验非空值为配置中有效的真实分组，拒绝 `auto` 等虚拟组；更新映射显式包含空值以支持清除，提交成功后失效计划缓存。公共套餐响应携带该字段；有效订阅摘要返回从当前计划读出的适用分组（即使计划后来停用，活跃订阅仍应正确显示），不把计划价格/用户组等扩展进快照。
- `model/main.go` 同时修改 SQLite 手动 `CREATE TABLE` 与 `required` 增列路径，MySQL/PostgreSQL 使用现有 AutoMigrate；无回填操作，现存计划以空字符串为不限。预扣幂等记录额外存储预扣时的真实计费分组和计划适用范围（空值兼容旧记录）；存量记录未知来源只能在当前计划仍不限分组时复用，计划已改受限则拒绝重放，避免误扣。迁移两次与旧数据/索引验证必须覆盖三方言。

## 请求/扣费数据流

1. 令牌鉴权/渠道选择确定请求分组，`auto` 解析到实际分组；计价阶段将实际分组写入 `RelayInfo.UsingGroup`。各 `PreConsumeBilling` 入口确认读取到真实分组，不将 `auto` 字面量视为 `deepflash`，未能确认实际分组时不得扣受限套餐。渠道 ID 不是适用性依据。
2. `NewBillingSession` 将实际分组传给 `SubscriptionFunding`，后者传到 `model.PreConsumeUserSubscription`。在锁定订阅候选的事务中按**当前计划**的 `ApplicableGroup` 过滤后，才进行额度重置/余额判定和幂等预扣记录创建；只用一个能覆盖全额的匹配套餐，保留当前按到期时间排序。读取计划适用分组的资金决策不得使用可能陈旧的缓存；请求开始后管理员并发修改按事务观察到的配置为准。
3. 明确区分「无活跃订阅」「有活跃订阅但无适用套餐」和「有适用套餐但不足额」；使用可 `errors.Is` 的哨兵错误而非错误文字判断。`subscription_first` 对无匹配直接尝试钱包，即使不匹配套餐禁止溢出；若匹配但余额不足，只考虑**当前分组匹配的活跃订阅**的 `AllowWalletOverflow`（任一匹配套餐禁止则不回退，沿用现有保守语义）。`subscription_only` 无匹配报额度错误；`wallet_first` 仍优先钱包，余额不足才试匹配套餐；`wallet_only` 不试套餐。
4. 预扣完成后会话绑定订阅 ID 和当时的适用范围；预扣幂等重放只接受同一用户和同一实际分组，返回原记录的范围而非后来编辑的计划值。并发时先锁定用户的活跃订阅，再以 `lockForUpdate(tx)` 对请求 ID 进行当前读，避免 MySQL 事务快照遗漏另一事务刚完成的预扣；唯一索引冲突直接回滚，不能依据 MySQL 可受 `clientFoundRows` 影响的冲突插入 `RowsAffected` 扣账。结算补扣、差额退还和失败退款仍针对原 ID，当前计划后来编辑不迁移已开始请求的资金来源。保留令牌预扣失败时的回滚和一次请求不能拆分跨套餐的不变量。

## 前端体验

- 复用管理表单现有 `Combobox` + `getGroups`，新增与升级分组分开的「适用分组」选择，提供「全部分组/不限分组」；`plan-form.ts` 默认值/编辑回填/提交和 `types.ts` 一并更新，前后端校验一致。
- 管理表列复用 `GroupBadge`，公共购买套餐卡与确认弹窗显示该组/不限；有效订阅卡展示服务端提供的当前适用范围，避免管理变更后仍显示旧购买时信息。继续使用现有 UI 组件，不新建同类选择器。
- 新 UI 文案用英文 `t()` key，按 `.agents/skills/i18n-translate/SKILL.md` 通过已有 `web/scripts/add-missing-keys.mjs` 一次更新七种语言，再运行 `bun run i18n:sync`；不手改 locale JSON。

## 兼容、取舍和运行

- 不复用 `UpgradeGroup`，避免存量套餐突然受限；不绑定渠道 ID，避免重试/渠道变更绕过；只支持单组，以后若需多个组另行定义迁移。
- 多个匹配套餐依旧最早到期且单笔足额；不匹配的严格套餐不阻挡钱包。若无真实分组、套餐配置丢失或数据库查询失败，不得通过「不限」/钱包回退掩盖异常；区分正常无匹配与读库异常。
- 管理员把 `deepflash` 改为其他组会改变**所有活跃订阅**的未来可用范围，建议界面文案显式说明；不追溯历史消费。缓存失效需在成功更新后发生；为避免失效窗口，消费判定读事务中当前计划记录。
- 回滚：停止发布/隐藏受限套餐并将 `applicable_group` 清空即可恢复不限分组行为；保留新列和旧数据，代码回退若 schema 含额外列仍需核验 ORM 兼容，不能直接丢列。
