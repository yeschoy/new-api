# 技术设计

## 边界与路由

- 保留 `/` → `Home`、`/activity` → 公开活动页的 URL 与路由属性。将现有 `CashbackActivityPage` 作为首页活动期间的默认内容复用；将 `/activity` 的组件改为两款狂蹬卡介绍页。两个交付物共用营销导航和路由状态，作为一个集成任务验证，不建立互相依赖的子任务。
- `Home` 继续先等待 `useHomePageContent`，然后优先处理自定义内容；仅在无自定义内容时根据**固定绝对时刻**判断返现页或原 `DefaultHome`。北京时间 2026-10-08 00:00 = UTC 2026-10-07 16:00。用一个截止定时器，并在窗口重新聚焦／恢复时复查时间，避免页面保持挂载或设备休眠后显示过期活动；清理监听与计时器。系统时间仅控制展示，不能成为支付或资格授权。
- 返现页仍订阅匿名 `public-offers`，保留每 30 秒／focus 刷新以及刷新、失败时隐藏旧规则的行为。避免对真实返现服务端活动添加前端固定日期校验：即便首页限时可见，真正是否奖励仍由服务端在付款时决定。

## 活动页内容与导航

- `/activity` 使用现有营销页布局、Header/Footer 和活动页样式，展示两个可区分的产品介绍卡：DeepSeek 狂蹬卡、GPT 狂蹬卡。说明仅表达“到钱包查看当前可售套餐及具体权益”，不宣称无限量、折扣、套餐一定存在或特定价格；产品标题使用专有名词配合翻译。卡片行动：登录后 `/wallet`，访客 `/sign-up`。不读取认证计划接口，不绑定前端猜测的套餐 ID、标题关键字或配置。
- 公共导航按照实际所在页设置 currentPage。营销导航里原 `/#models` 在返现页充当首页时会变成无效锚点；在没有模型区的页面隐藏或替换该入口为实际可访问的目标，不影响恢复后的默认首页模型锚点。
- 沿用活动页现有卡片 CSS 与响应式／暗色主题；对比项目基础 `Card`、`TitledCard`，这两个基础组件用于控制台卡片，不承担现有营销页视觉与活动布局，优先扩展已有 `activity-*` 表现，避免双套装饰。

## 文案与兼容

- 新文案通过 `useTranslation` 订阅语言，在七种 locale 中补齐；locale 文件只能经 i18n 技能规定的脚本写入并执行 `bun run i18n:sync`。
- 保留 `/activity` 路由而改变内容属于用户已确认的产品重定向；历史直接链接不再显示返现页。在活动期内，返现活动可通过首页访问；结束后默认首页恢复后不提供旧返现活动的公开展示入口，这是活动限时呈现的预期结果。返回原默认首页不需要部署新版本。
- 不修改后端、数据库、鉴权、订单、返现或订阅套餐的业务状态；配置异常／网络失败继续走现有安全降级。

## 验证与回退

- 用固定／模拟时钟测试截止前、边界、持续打开跨界、自定义首页优先级；用 React 测试验证返现页最新状态、新 `/activity` 页面与访客／登录 CTA，移动与导航状态。人工浏览器检查桌面／窄屏、明暗主题和语言切换。
- 如要回退，可以恢复首页默认渲染及 `/activity` 原组件映射；没有 schema、配置迁移或用户资金变化。注意两者需一并回退，避免两个路由内容丢失或重复。
