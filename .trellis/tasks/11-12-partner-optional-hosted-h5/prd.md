# 商户可选托管 H5 套餐购买页

## 目标与价值

增加由平台托管的完整套餐购买 H5，商户只需对接购买入口和用户身份，不必重复开发套餐选择页面；现有自建前端/API 接入保持可用。

## 已确认的产品决策

- 用户明确要求实现完整购买 H5，而不只是已有的单笔订单收银台。
- H5 是可选入口：商户可使用 H5，也可继续自建页面；同一商户不必在两种方式之间做互斥迁移。
- 用户已选择 **A：独立 H5**，通过链接、新窗口或 App WebView 打开；第一版不做 iframe。
- 两种入口共用订单、支付确认、自动开户和套餐交付规则，不建设第二套计费系统。

## 背景与约束

- 当前目录接口按商户隔离（`controller/partner_tenant.go:223`），现有订单创建包含幂等及支付准备（`controller/partner_tenant_order.go:160`）。
- 公开收银台能力只绑定单笔订单（`controller/partner_tenant_order.go:273`），不能直接授予选套餐、切换购买人等权限；新购买入口必须具有独立的限权边界。
- 现有收银台 HTML 禁止 iframe（`router/web-router.go:29`）；商户配置无嵌入白名单（`model/partner_tenant.go:33`）。选择独立页后保留该安全基线。
- 现有商户付费链路仅支持 CNY；历史非 CNY 套餐不能自动改币种或换算。付款与交付分别表达，浏览器不能确认收款。
- 工作区已有未提交的接入文档、Demo、报告、临时产物记录及凭证文件，必须保留用户已有内容；不得读取/提交私钥、混入无关改动或未经许可清理产物。
- 完整现状证据见 [current-contracts.md](research/current-contracts.md)。Docker 当前不可连接，Go/数据库运行验证存在环境阻塞，不能用编译或页面模拟替代。

## 需求与验收标准

| ID | 需求 | 可观察的验收标准 |
| --- | --- | --- |
| R1 | 完整、移动端可用的托管购买体验 | 打开入口后无需登录平台注册账号；可查看本商户当前可售套餐及真实 CNY 价格、选择套餐和可用支付方式，进入现有收银台，并查看付款/交付状态。桌面及 390px 宽页面无横向溢出。 |
| R2 | 保持 H5 可选及既有合同兼容 | 未使用 H5 的商户无需改动；现有套餐、开户、下单、查单、额度接口及收银台链接的请求/响应和行为不变。不引入强制互斥的 API/H5 模式。 |
| R3 | 可信购买身份和租户隔离 | 购买人由商户后端登录态确定；浏览器不得通过提交其他 tenant/user/order/金额改变购买归属。商户密钥、模型 Key 和平台登录态均不进入 H5。跨商户、跨用户和无效会话请求被拒绝。 |
| R4 | 安全的限时购买入口 | 入口短期有效且兑换为限权会话；刷新/同请求重试不延长有效期。错误、过期、撤销及另一个窗口使用过的入口有明确提示，不要求登录平台、不静默创建新订单。敏感入口不被埋点、URL 查询、缓存、日志或 referrer 泄露。 |
| R5 | 单次购买幂等与失败恢复 | 每次购买入口最多对应一笔订单；双击、同标签页刷新和请求超时后恢复原购买参数/原订单，不重复收费。同入口更换已下单的套餐/渠道返回冲突而不是生成另一订单；新的购买需从商户重新发起。 |
| R6 | 共用权威计价、支付及交付 | 套餐目录不展示不可支付的历史外币套餐；下单时服务端再次验证有效性与价格，收银台展示订单最终金额。复用既有订单快照、限购、渠道验签、已付款事实与自动开户交付，不因关窗而中止交付，不重复续期。 |
| R7 | 商户能跟踪 H5 购买结果 | 商户后端使用已保存的购买会话标识查询是否已形成订单和相应订单状态，并核验购买人归属；不依赖浏览器回跳或 webhook。已付款未交付明确提示等待且不要重复付款。 |
| R8 | 隔离的公开页面 | H5 和旧收银台均不运行平台登录/刷新、setup、全局状态/奖励/分析等副作用；保留 no-store、no-referrer、禁止嵌入及编码路径保护，普通页面不受影响。 |
| R9 | 接入文档、多语言和回归验证 | 文档并列说明 API/H5 两条路径、商户后端职责、幂等/过期/恢复/查单及凭证保护；新 UI 文案覆盖全部七种现有语言。自动化覆盖新入口和旧 API 兼容，明确区分模拟页面检查与真实数据库验证。 |

## 范围之外

- iframe、postMessage、跨站完整账号 SSO、商户网站重建、商户品牌/主题编辑器。
- 强制切换接入模式、替代或废弃现有 API、允许商户或浏览器申报已付款。
- 任意 return_url、自动跨站回跳、WebView 原生桥；第一版以现有收银台结果页提示用户返回商户。
- 自动续费、商户钱包、新支付渠道、退款、商户 webhook、模型/额度算术调整。
- 无凭证的公共商城、跨设备无条件恢复已兑换入口、过期后自动重新收费。
- 生产部署、真实交易/开户、未经授权的生产配置/数据库操作或数据清理。

## 风险与完成边界

- 支付渠道可能要求外部页面；支持独立 H5/WebView 不等于承诺所有第三方付款可在任何 WebView 内完成。
- 浏览器存储不可用时允许当前页面内存回退，但刷新/跨设备恢复受限，必须提示回商户查单，不得盲目新建购买。
- Docker 不可用时只能报告实际完成的静态/前端检查，后端数据库、迁移、并发及支付回调测试仍为阻塞项，不得宣称全量验收通过或归档为完成。
