# 执行计划：充值页返现预览

1. 在服务端现有返现测试文件先写预览回归：比例/每满百规则、面额 vs 实付、单笔/24 小时限额、活动时间与次数、无活动/资格、零额、欠额、Creem 产品/标准支付、无数据泄露；确保与支付成功计提公式/限额一致且预览不修改数据库。
2. 在 `model/` 增加有界只读估算读取，在 `controller/` 和已认证用户路由添加严格校验的预览接口。预览不可成为实际奖励输入；支付完成仍按原有服务端条件计算。
3. 按 `web/AGENTS.md`、`shadcn-ui`、`vercel-react-best-practices` 检查已有组件/数据获取模式，将服务端估算接入钱包金额输入与 Creem 产品确认；防止过期请求覆盖。补充加载、空/无资格、失败、金额切换、响应式组件行为测试。
4. 根据 `i18n-translate` 只经脚本添加/修改七语文案，执行 `bun run i18n:sync` 并清理此次临时脚本；不新增插件目录或 docs 文件。
5. Go `gofmt`、聚焦测试、前端 Vitest/typecheck/lint/build；真实 SQLite/MySQL/PostgreSQL 实例验证受影响查询和支付计提对比，记录版本、命令与结果。必要时按项目迁移标准完成升级/重复启动验证。
6. 由 `trellis-check` 复核安全信息边界、金额计算和前端用户体验；缺陷回到第 1 步。检查 diff、更新规范、提交产品及 Trellis 改动，再由父任务做跨任务验收。
