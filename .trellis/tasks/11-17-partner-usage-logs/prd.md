# 商户模型日志独立存储与后台用量页

## 目标与归属

父任务 `../11-17-partner-usage-isolation/`，承接 R1/R2/R5/R6/R7；AC1/AC2/AC5/AC6/AC7/AC8。以端到端交付避免只切写入却没有查询入口。父任务最终完整规划已于 2026-11-17 续接会话获用户实施批准（见父 prd“授权与阶段”）；本子任务按 A/B/C/D 阶段交付。

## 需求

- **U1**：新 Tenant 模型调用成功消费、零消耗和现有可记录失败单写独立表。保留开关/抑制，不额外收集正文或强制记原本未记失败。仅关联已验证身份，无已选订阅的失败不伪造 subscription_id；普通订阅/OAuth/Server 不误分类。
- **U2**：用户已确认旧日志默认页保留原有展示/统计，新页只含新表数据并说明切换范围；不迁移、删除、隐藏旧日志。
- **U3**：管理员页提供商户/时间/账号/模型过滤、分页明细与同口径消耗、请求及 Token 统计；默认管理员日志和导出不合并新表。
- **U4**：保留服务端请求关联、消费、Token、计费来源和安全商户归属；CNY 使用统一契约，不重复发明金额算法，不写密钥/种子/请求正文/凭证响应。
- **U5**：日志不成为计费提交条件，不改变支付、预扣/结算/退款、订阅、钱包/Token 实扣。
- **U6**：用户已确认全站仪表盘仍包含商户消耗，既有全站聚合按原规则写入一次；日志分表不等于全站统计隔离。
- **U7**：用户已确认个人 self 列表、统计、请求结果/汇总、已有自身导出及 token 最近记录连续读取旧/新数据，限定已鉴权身份并保持脱敏；不双写、不新增权限。
- **U8**：用户已确认普通管理员/root 均可只读查看新页和安全商户选项，PAT 及 admin/root 分层仍生效；商户密钥/配置管理继续仅 root。

## 验收标准

- **A-U1（AC1）**：各实际写入口证明目标仅一处一行，覆盖成功、零额、可记录失败、失败重试、文本/音频/流和受支持任务；原抑制不绕过，无猜测归属。type=consume 的真实费用仍保留，type=error 不新增消费。
- **A-U2（AC5）**：隔离 PostgreSQL 真实证明共享/独立 LOG_DB 首次/重复迁移、持久化及索引；保留驱动兼容，不扫描搬迁 logs，ClickHouse 使用明确 DDL/TTL。
- **A-U3（AC2/AC5）**：total、过滤、分页、金额/请求/Token 统计同范围；旧行在默认页可查，新行不双计，新页不暗示历史完整。
- **A-U4（AC8）**：真实生产路由鉴权覆盖匿名/用户/admin/root/PAT，选项仅安全字段，admin/root/user 投影不串级，root-only 管理 API 未放宽。
- **A-U5（AC2）**：加载/错误/空态、键盘/移动端、切换商户与七语言正确；查看者/过滤状态缓存隔离；不复制整套默认日志 feature。
- **A-U6（AC1/AC5）**：归属或新表日志故障不回写默认表、不回滚已结算额度，安全告警不含原始 SQL/正文/秘密；可能漏记明确披露，不声称跨库无损。
- **A-U7（AC6）**：分流消费仍按既有规则进入全站聚合一次；失败/零额按原计数处理，不另造消费，默认顶部不读新表。
- **A-U8（AC7）**：所有已有自身入口均覆盖旧/新记录，分页/count/排序/消耗一致；ownership 在 union/分页前施加；同 ID 不冲突，request_id 重试折叠规则保持，无外部选择器越权。

## 不在范围

历史搬迁/隐藏/清理执行、复杂报表、新导出系统、商户自助后台、正文审计、计费重构、生产变更。现有业务/安全/凭证审计不是本表替代目标。

## 依赖与阶段

本子任务先交付安全归属基础契约，用户分类子任务再消费；CNY 子任务独立交付换算契约后，本页才接入金额。父/子 design 与 implement 记录具体依赖、失败策略和回归门禁。产品问题已收敛；最终摘要获后续批准之前不 start、写业务代码或运行业务测试。
