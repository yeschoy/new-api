# AdsPower / FlashIP 购买链路研究与商户套餐方案

## 目标与授权边界

调查 AdsPower 内购买 FlashIP 的公开实现证据，并收敛本项目网页商户销售专属模型套餐的最小方案。当前任务包含研究与实施规划，不代表批准业务代码、数据库、线上配置或部署；保持 planning，最终规划须在后续消息获明确批准后才进入实施。

## 背景与已确认决定

- 用户提供 AdsPower 购买代理弹窗截图，希望自己的商户网页也能展示专属商品并完成购买。截图仅证明可见 UI，不证明真实网络架构或商户隔离。
- 用户同意第一版采用“商户自建套餐展示/购买弹窗 + 我方统一收银台、订单和后台交付”，不建设整套托管商城 iframe 或通用跨站 SSO。用户不必注册、登录我方完整账号。
- 用户明确说明“目前没有真实商户，不用兼容”。因此不保留 Tenant 旧的商户直接开通合同，不新增新旧模式开关或双轨逻辑；未来商户只能通过我方确认付款的订单获得套餐。
- “无真实商户”是用户对兼容需求的确认，不是删除测试账号、订单、订阅或清空数据库的授权，也不是删除独立 OAuth、PartnerServer 钱包充值或普通用户支付产品的授权。
- 2026-11-11 公开代码证实 AdsPower 自身存在 Vue BuyProxy/PayDialog 与宿主商品、报价、购买调用点，供应商枚举明确 `flashid -> FlashIP`。FlashIP 独立控制台另有授权码、订单号/支付链接与延后 3 秒查询代码，不能作为 AdsPower 入口的同一协议证据。来源、hash、偏移与未知见 `research/REPORT.zh-CN.md`。

### 已收敛的第一版产品合同（待最终实施批准）

| ID | 需求 | 可观察验收 |
| --- | --- | --- |
| R4 | 商户在自己的网页展示本商户专属套餐，选择后通过自己的后端下单 | 商品查询和下单均按认证租户校验可售范围；前端不能伪造用户、跨商户套餐或金额。external_user_id 由商户后端可信登录态映射，pt_ 不进入网页 |
| R5 | 我方生成订单、权威计价并提供统一收银台 | 商户不必生成我方业务订单号或自行收款；重复同一幂等请求只对应同一订单。收银台只能访问指定订单，不暴露商户 secret/模型 Key，也不要求完整平台账号登录；渠道支持二维码或外部跳转，不保证 iframe 付款 |
| R6 | 我方验证付款后自动交付，必要时创建缺失账号并开通/续期套餐 | 未付款不产生套餐权益；独立取 Key 可以提前创建空账号但不赠套餐。可信付款事实持久保存；账号/Key 复用或初建、套餐变更与唯一交付标记原子提交；重复回调/重试不重复续期 |
| R7 | 交付不依赖浏览器保持打开，失败可恢复 | 订单分别表达付款和交付状态；关窗后后台仍处理，商户重新打开后可查询。已付款但交付失败不再次扣款，保留 paid 并重试/告警；禁用账号或撤销凭证不能被静默替换 |
| R8 | 独立取得用户 API Key，模型消费强制仅套餐 | 独立接口幂等初建/获取同一可用 Key，不触发订单或权益；Key 不出现在支付链接/订单状态。即使钱包有余额或用户偏好钱包，无适用套餐/额度时也不回退钱包；普通用户和独立充值产品不被误改 |
| R9 | 只提供平台收款的 Tenant 套餐购买合同，不兼容旧外部直接开通 | 商户不能再调用旧 Tenant grant 路由绕过付款；不引入 legacy/new 模式开关；内部套餐交付能力仅由已核实付款的订单驱动，旧文档/样例/测试同步更新 |

## 范围

后续我方实施范围为 Tenant 套餐订单、统一收银台、可信支付确认、自动开户/套餐交付、查询/重试、独立 Key 安全约束、仅套餐计费及接入文档。商户自己维护其业务前端/BFF，本仓库提供合同和示例，不假装已修改商户网站。

研究与规划可以在当前任务完成；业务实施应承接已有 `.trellis/tasks/11-04-partner-subscription-auto-provision/`，同步其过时规划并通过最终门槛，不并行建设第二套套餐订单系统。

## 范围外

- 真实登录、下单、付款、生产访问、区域限制绕过、扫描猜测私有接口、客户端安装或未提供二进制逆向。
- 兼容旧 Tenant 直接开通合同、双模式开关、整套托管商品商城 iframe、通用跨站 SSO。
- 商户钱包/信用结算、自动续费、新支付渠道、退款自动化、商户 webhook 的实现；优先复用现有可用支付能力，后续需求另行规划。
- 删除历史/测试数据、重置数据库、合并或删除 OAuth/PartnerServer 账号体系、修改普通用户充值或支付产品。
- 本轮业务代码、数据库迁移、前端开发与部署；已有未提交文档和生产验证报告保持不变，待实施按差异合并。

## 风险与明确限制

- 竞品 B2B 关联、真实支付验签和关窗付款交付仍未运行时验证；不阻塞自主方案，也不能据此宣称完成私有协议逆向。
- 支付渠道主动查单和回调丢失恢复必须按其安全合同设计，不能复用会在 URL 泄露密钥的调用；已付款与交付事务不能混为可回滚外部资金。
- 收银台短期订单访问、幂等、跨租户隔离和多数据库事务需要实施时的隔离测试；尚未执行应用构建、数据库测试或支付沙箱测试。
