# AdsPower / FlashIP 内嵌购买取证与商户专属套餐方案

## 目标

在不访问未授权资源、不登录未知账号、不真实下单或付款、不修改业务代码的前提下，调查 AdsPower 内购买 FlashIP 的真实集成方式，并为本项目商户网页销售模型套餐提出最小方案。此任务为研究及后续实施规划；不代表批准开发或部署。

## 用户确认的需求

- 核实 FlashIP 与 FlashID 的产品、入口及文档命名差异，不混为同一服务。
- 研究购买 UI 的部署维护方及 iframe / WebView / 托管 H5 / 宿主 API 界面之区别。
- 研究当前用户身份关联、免重复登录、订单创建与订单号、支付链接、付款验证、交付及结果同步；特别说明关闭窗口后的行为。
- 商户在自己的网页内展示、销售获准的专属模型套餐；我方生成订单、确认付款，交付时自动创建缺失账号并开通套餐。
- 独立提供用户 API Key 获取接口；模型消费仅走套餐、不回退钱包。
- 用户提供购买代理弹窗截图作为体验示例。截图仅证明可见 UI，不证明真实网络架构或商户隔离。

## 交付与验收

1. 每条竞品关键结论标注直接证据、合理推断或未知；公开来源保留 URL、观察日期和必要原文，区分搜索摘要和实际打开内容。
2. 提供竞品已证实/推断链路与我方建议时序图，不将未观察到的接口、授权码、轮询、webhook 或 postMessage 描述为事实。
3. 明确我方与商户前后端职责，包含专属商品可售范围、身份隔离、支付权威和后台持久交付。
4. 对照现有源码能力与缺口；建议接口显式注明未实现，不混用 Tenant 套餐身份与 PartnerServer 充值身份。
5. 给出最小方案与脱敏 HAR、DOM、JS 补证清单，包含哪些材料能证明或排除哪种架构。
6. 研究结论和方案落盘至本任务；无业务代码修改、生产访问或支付操作；不覆盖既有未提交资料。

## 范围外

- 支付、账号登录、区域限制绕过、扫描猜测私有接口、客户端安装或逆向未提供的二进制。
- 商户钱包/信用结算、退款、自动续费的实现；可记录后续选项但不擅自决定。
- 现有历史任务的实施、数据库迁移、前端开发或部署。

## 已核实的背景与交付状态

- 2026-11-11 公开代码取证发现 AdsPower 自身 Vue BuyProxy/PayDialog 与宿主商品、报价、购买调用点，比此前“供应商 H5”的假设更有依据；供应商枚举明确 `flashid -> FlashIP`。完整来源、hash、偏移与归因见 `research/REPORT.zh-CN.md`。
- FlashIP 独立控制台另有授权码、订单号/支付链接和延后 3 秒查询代码；这不能作为 AdsPower 内嵌入口的同一协议证据。供应商 B2B、真实渠道验签和关窗交付仍未做运行时验证。
- 已完成五项问题的证据分级、两条时序、职责/配置、当前项目差距和脱敏补证清单；`design.md` 与 `implement.md` 记录候选方案和后续门槛。

## 待用户决定的实施边界

研究交付不依赖进一步产品决定，但业务实施仍需选择 UI 所有权：推荐商户原生购买 UI + 我方订单/交付 API；备选我方统一托管 H5，减少商户前端开发但增加我方维护及嵌入兼容成本。后续还需确认旧直接开通合同的兼容边界。本任务保持 planning，不运行 task.py start，不将创建授权等同于业务实现授权。
