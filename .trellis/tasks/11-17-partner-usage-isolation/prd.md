# 商户用量独立存储、人民币额度与用户分类

## 目标与价值

将 Tenant 商户的新模型调用记录与默认用量分离，使管理员能独立排障和核对用量；商户获得可直接展示的 CNY 额度，用户列表能按真实商户归属分类。保留历史可查性及个人查询连续性，不改变支付、权益或实际扣额。

- 续接复核：用户要求检查已有多任务拆分及上轮缺口，授权本轮调整规划，未授权 start。保留父任务 + 三个子任务；执行/安全/回归缺口见 `research/planning-review.md`，须评审本次修订后的完整摘要。

## 背景与证据

- quota 为内部计量值，非货币或 Token 数。此前只读证据中，15000000 quota、quota_per_unit=500000、CNY 汇率=1 对应 ¥30.00；该示例不是硬编码换算规则。默认日志顶部消费统计包含订阅消费，不等于钱包扣款。
- 真实归属为 `model/partner_tenant.go:48,84` 的 Tenant 账号关系，与套餐有效期/账号启用状态无关。既有 OAuth 合作方筛选是另一套身份：`model/user.go:460-496`、`controller/user.go:395-435`、`web/src/features/users/components/users-table.tsx:96-192`。
- 日志写入口为 `model/log.go:279,340,427`；失败可能早于订阅选择，不能用 billing_source=subscription 代替商户归属。默认统计见 `model/log.go:738`、`web/src/features/usage-logs/components/common-logs-stats.tsx:69-93`。
- 共享/独立 LOG_DB 启动路径见 `model/main.go:236,443`；个人请求/汇总见 `model/log.go:620`、`model/log_summary.go:35`；全站小时聚合独立位于 `model/usedata.go:102`。
- 源码核对见 `research/current-boundaries.md`；跨子任务契约见 `research/contract-decisions.md`。前次五分钟订单修改已提交 `03008c73a`，不重新实现或扩大该支付范围。
- 前组 `11-13-partner-access-mode-audit/verification.md` 仍为 source-review-ready / runtime-blocked，两个实现子任务尚未归档。该既有运行缺口必须独立披露，不能随本组规划完成被视为已验收。

## 已确认需求

- **R1 — 单写独立表**：新 Tenant 模型调用的成功消费、零消耗和现有机制会记录的失败一起隔离，不再写默认用量表。保留错误开关/抑制策略，不新增请求正文采集、不补记原本不记录的鉴权/预扣失败，不为尚未选定订阅的失败伪造关联。普通订阅和非 Tenant Partner 调用不误分流。
- **R2 — 管理员商户用量页**：新增商户、时间、账号、模型筛选，分页明细及同条件统计。默认管理员日志/顶部统计排除这部分新记录；全站仪表盘仍包含商户实际消耗，保持真实平台总量。
- **R3 — CNY 额度**：商户接口兼容新增人民币总额、已用、可用剩余，金额为十进制字符串并明确换算/舍入规则。原 quota 字段/类型保留，不限量不得误显示为零余额；这是额度展示，不是钱包或套餐售价。
- **R4 — 用户分类**：全部/普通/商户分类、所属商户列、具体商户筛选，以真实 Tenant 关系为准；禁用/过期不使商户身份变普通。不新增角色/VIP/权限；保留既有 OAuth 合作方字段和筛选。
- **R5 — 自身读取连续**：个人列表、统计、请求结果/汇总、已有自身导出和 API Key 最近记录兼容读取有权查看的旧/新记录，按已鉴权 user_id/token_id 限定并脱敏。底层仍单写，不新增登录/商户后台权限。
- **R6 — 管理员只读权限**：普通管理员和 root 均可查看新用量页、用户所属商户及安全筛选选项，沿用管理员日志的读取边界；保留 PAT 约束和 admin/root 信息分级。商户密钥/配置管理仍仅 root，普通用户仅保留 R5。
- **R7 — 历史过渡**：用户已确认旧商户日志留在原表、默认页继续展示和统计；新商户页仅展示切换后写入新表的数据，明确提示范围。不迁移、隐藏或重算旧记录。

## 验收标准

- **AC1（R1）**：真实写入口验证成功、零消耗、现有可记录失败仅写新表；普通/非 Tenant 订阅仍写默认表。失败重试链可在商户页查；type=error 不累计消费，既有收费事实（包括被记为 consume 的费用）不被清零或重算。日志开关/抑制规则不变。
- **AC2（R2/R4/R6）**：商户列表 total/分页/筛选和统计范围一致；用量页与用户页归属一致，无未授权商户/敏感凭证泄露。
- **AC3（R3）**：原 quota 不变，新增 CNY 不丢失大整数输入精度，披露小数舍入；正常/耗尽、不限量、到期/取消、历史余额、小额、非法换算配置均有正确结果。
- **AC4（R4）**：分类与商户过滤在分页前生效，count/行数据一致，与关键词、状态、角色、组、排序组合正确；不改变账号/角色/套餐权益。
- **AC5（R1/R7）**：共享与独立 LOG_DB 均建立新表；不搬迁旧日志。默认页仍可追溯旧记录，新页提示仅含新数据；索引、保留/清理边界及日志故障行为明确。
- **AC6（R2）**：新商户消费排除于默认日志顶部，但既有全站小时聚合/真实计费计数继续按原规则计入一次；错误记录不新增消费，不因分表双计或漏计全站用量。
- **AC7（R5）**：自身旧/新列表、count、分页、汇总、请求去重与已有导出连续；同表/跨表 ID 相同不丢行，重试结果保持既有规则。伪造 user_id/tenant_id/token_id 不能越权；默认管理员全量查询/导出不得 union 新表。
- **AC8（R6）**：匿名/普通用户无法进入管理员读取接口；普通管理员/root 可只读使用，PAT 受原路由资源规则约束；root-only 管理 API 及字段脱敏不降级。

## 不在范围

历史迁移/删除/重算、数据修复、商户自助后台、复杂报表、新导出系统、收费/售价/汇率重做、支付/退款/开户/续费/实际扣款行为变更、角色调整、将全部订阅或 OAuth/Server 身份视为 Tenant、生产变更/部署/真实消费测试。
