# 充值人返现即时结算、自动审核状态与充值页预览

## Goal

使充值人返现审核通过后安全、及时到账；消除零额已取消记录的误导性“待审核”；在充值页同时呈现当前活动规则与本次预计奖励。

## Background / Confirmed Facts

- 截图 #395：充值人、严重风险、已通过/冻结中、待发 1、原始计算 1,500,000、显示可发放时间 2026-10-07 04:36。`model/cashback_rewards.go:274` 以支付成功 + T+N 初始化 `available_at`；`model/cashback_state.go:198-215` 审核通过仍等待该时间。
- 配置截图：充值人自动审核及“自动批准后立即发放”开启，四档“需人工审核”均关闭。截图 #396：严重风险、待审核/已取消、待发 0。`model/cashback_rewards.go:194-250,283-313` 对零额奖励先取消，仅对正额充值人奖励运行自动审批，因此可生成 `pending/canceled/0`，并非真实待办。截图不能确定 #396 具体是何种封顶/取消原因，详情中的 `cap_reason`、`blocking_reason` 是确认依据。
- 充值页 `web/src/features/wallet/components/recharge-form-card.tsx` 只有金额、支付方式及其他钱包功能；`controller/topup.go:24` 的 `/api/user/topup/info` 没有用户活动资格和返现预估数据。
- 原合同 `.trellis/spec/backend/referral-recharge-cashback.md` 与既有任务 `09-24-standalone-topup-cashback-auto-review/prd.md` 规定人工审核充值人奖励也等 T+N；本请求明确改变该点。支付安全、邀请人方向和自动批准后立即发放开关的原有边界不因此取消。

## Requirements

1. **充值人手审即时发放**：人工审核通过的合格正额充值人奖励，包括已批准但仍冻结的存量记录（如 #395），无需等待原 T+N，经支付、异常、欠额、对账、额度与幂等校验后及时发放；不重算历史奖励额、冒充支付成功或放行未审核/已取消记录。邀请人方向仍走既有 T+N；自动批准但关闭“立即发放”开关的记录仍遵守该开关语义。
2. **免审状态与零额已取消**：充值人开启自动审核且对应风险档无需人工审核时，合格正额奖励按配置自动批准，不因严重风险标签本身被要求人工审核；`pending/canceled/0` 等已取消记录在列表、详情和待审核筛选/统计中不再被误认为待办，同时保留取消原因及历史风险/审核证据，不从零额记录发钱。
3. **充值页规则与个性化估算**：用户明确选择二者都展示。选定充值金额时展示当前适用活动的返现规则（百分比或每满 100 固定额）和基于当前账号/金额/活动/限额/次数的本次预计返现；无资格、零额和信息不可用时不得展示确定的正额承诺。页面明确说明预估可能随活动、24 小时额度、支付时间/校验变化，最终以支付成功后的计提/发放为准；不向用户暴露风控证据或管理员敏感配置。
4. 三项交付分别可验证，但须在用户可见状态、历史兼容、七语 i18n 与安全资金校验上完成整体验收。不得把前端估算当服务端计提输入，也不得绕过活动、次数上限、支付验签和退款/欠额处理。

## Child Tasks / Integration

- `09-30-payer-manual-issue`：手审后即时发放及已批准存量冻结奖励。
- `09-30-payer-review-zero-state`：免审的零额取消状态与历史列表/筛选。
- `09-30-payer-topup-preview`：充值页活动规则与个性化奖励估算。
- 子任务各自完成规划、实现、检查和提交；父任务仅负责跨子任务一致性复核与总体交付，不直接承载产品代码。

## Acceptance Criteria

- [ ] 人工审核通过的正额充值人返现，包括 #395 型历史已批准冻结记录，在资金安全校验通过后及时且至多一次入账；无通过则明确阻断/重试。邀请人 T+N、充值人自动批准但关闭即时开关的旧行为不变。
- [ ] 开启免审且四档人工审核都关闭时，合格正额严重风险充值人返现也自动批准；#396 型零额已取消记录不出现在有效待审核待办，不显示错误的待审操作，同时保留取消原因且不授信。
- [ ] 充值页面随预设/自定义金额变化同时显示适用活动规则与该用户本次预计返现；不适用时显示可信的无资格/零额状态；明确“预计非到账承诺”，支付实际计提与预估互不替代。
- [ ] 关键状态流、历史兼容、并发幂等、预览边界、七语 i18n 与三数据库受影响行为获得验证；整体验收确认账务与界面表达一致。

## Out of Scope

- 变更邀请人 T+N、支付渠道的结算/验签规则、自动退款/拒付回调、现金提现或历史返现额重算。
- 根据前端估算提前冻结奖励名额、锁定每日额度、绕过支付成功后的风险及账务检查。
- 把已取消的零额记录变成可发放奖励，或为消除待审标签伪造历史审批日志。
