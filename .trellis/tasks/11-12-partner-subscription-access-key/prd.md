# 商户开发者密钥下单与独立订阅 Key 查询

## 状态与原始需求

- 状态：planning；原订阅 Key 生命周期方案已呈现，用户新增“为商户配置可订阅套餐”，需要补充套餐授权范围后重新审阅。未批准实施，未运行 `task.py start`，未修改业务代码。
- 原始需求：“再新增一种对接方式，商户通过开发者秘钥鉴权来生成订阅订单接口”；用户进一步澄清付款后交付的是单独订阅 Key，另设接口通过此 Key 取得“订阅信息、剩余额度、apikey”，不是用它直接调用 Coding。
- 后续明确决定：商户后端领取并交付（A）；同一份订阅续费沿用原 Key（“要”）；到期可查历史但不返回 Coding API Key（“可以”）；本期增加商户端重置订阅 Key（“好”）。上述答复不等于最终技术方案已获实施批准。
- 用户新增约束：“记住写完之后只做有必要的测试，不需要做过多无关的测试”；进一步指定“不需要验证sqllite，只需要验证pq”。因此只做本功能必要的 PostgreSQL 验证，不运行 SQLite/MySQL 测试。
- 用户新增要求：“并且这里我需要为商户可以配置可订阅的套餐”；另强调“订阅key是可以获取到信息的，是不需要再要商户秘钥来”。查询仅需订阅 Key，无额外商户凭证或商户上下文。

## 目标与用户价值

商户通过服务端开发者凭证创建付费订阅订单，买家付款后获得独立订阅凭证；买家无需持有商户秘密即可读取所购订阅权益及实际 Coding 调用凭证。既有商户 API 和可选托管 H5 保持可用，不要求调用方切换。

## 仓库背景与约束

- `middleware/partner_tenant.go:15`、`controller/partner_tenant_order.go:160`：已有 `pt_` 商户鉴权及订阅订单，含 external_user_id、plan_id、payment_method 与幂等请求机制，可以复用。
- `model/partner_tenant_order.go:361`：可信支付后原子创建/复用账户及 Coding API Key、授予订阅并记录订单 SubscriptionId；支付事实独立于本地交付，失败可恢复。
- `controller/partner_tenant_order.go:250`、`:279`：现有商户查单和公共收银台不返回任何用户调用凭证；本次不扩大它们的 DTO 权限。
- `model/partner_tenant.go:45`、`:255`、`:392`：同商户用户绑定一个账户级 Coding API Key，可有多份订阅；同套餐有效期内购买通常续期同一订阅行。
- `controller/partner_tenant.go:162`、`model/subscription.go:908`：旧额度查询返回账户下所有有效商户订阅，按实际订阅用量与周期重置计算，不能原样作为单订阅 Key 的授权范围。
- `controller/partner_tenant.go:83`、`model/partner_tenant.go:169`：现有重置只针对商户开发者密钥，不能代替单份订阅 Key 重置。
- 取证明细见 `research.md`；支付和 H5 既有安全约束分别由 `.trellis/spec/backend/partner-tenant-checkout.md`、`partner-hosted-h5.md` 定义。本记录不表示已有功能已上线或数据库/支付集成已通过。

## 需求

| ID | 已确认要求 |
| --- | --- |
| R1 | 作为新增对接方式支持商户开发者密钥鉴权下单，复用现有支付能力，保持现有接口及接入路径兼容。 |
| R2 | 付款并交付完成后签发独立订阅 Key，与商户开发者密钥、Coding API Key 的秘密值和用途不同。 |
| R3 | 新增独立查询接口，**仅以订阅 Key 鉴权，不再要求商户开发者密钥、商户登录态或商户 ID**，返回该份订阅信息、实时剩余额度及实际 Coding API Key；终态限制见 R9。 |
| R4 | 订阅 Key 本身不能调用 Coding，也不能读取同账户其他订阅或其他用户的数据。 |
| R5 | 仅可信支付确认且本地交付完成才可领取；浏览器回跳、客户端已支付声明不能触发授权；重复通知和恢复不得重复签发或重复开通权益。 |
| R6 | 将订阅 Key 当作能读取 Coding API Key 的敏感凭证处理；不进入 URL、日志、公共缓存或无关响应。额度不允许因客户端数字精度丢失而失真。 |
| R7 | 采用商户交付：商户后端用开发者密钥领取，校验订单买家后交付给用户。公共收银台及 H5 不展示或返回订阅 Key。 |
| R8 | 同一份订阅续费保留原订阅 Key，查询展示更新后的有效期和当前额度。不同订阅及到期后新建的订阅不自动合并。 |
| R9 | 到期后原订阅 Key 仍可查看该订阅信息、已到期状态与历史额度统计，但不返回 Coding API Key；历史余额不表示可消费权益。 |
| R10 | 本期提供仅商户后端可调用的订阅 Key 重置能力；换发新 Key 并立即使旧订阅 Key 失效，不改 Coding API Key 或订阅权益。 |
| R11 | 平台方可以为商户配置允许订阅的套餐；商户套餐列表和实际下单必须遵循配置，不能通过直接传未授权 plan_id 绕过。套餐采用商户专属归属还是多商户共享授权，待确认。 |

## 范围边界

- 本期包含商户可订阅套餐配置、服务端凭证签发、商户领取、专用查询、商户重置、迁移、必要测试、接入文档与安全规范；优先复用已有后台入口，不新增面向买家的平台页面或商户 webhook。
- 订阅查询只访问一份订阅；返回的 Coding API Key 仍是现有账户级凭证，**查询隔离不是 Coding 消费按单份订阅严格隔离**。
- 不替换模型 TokenAuth、钱包/订阅计费算法、额度单位、套餐价格、支付渠道或既有 RPM 规则。
- 不自动给历史已交付订单补签 Key，不改变历史订单及账户。新发生的真实付费续期可首次为其关联订阅建立凭证，不靠 GET 开户、授予或补发。
- 重置只阻止旧订阅 Key 的后续使用，不能撤回此前已经取走的 Coding API Key 或已经发送的查询响应；不增加 Coding API Key 自动轮换、根秘密轮换/KMS、独立撤销开关或自动退款。
- 不包含生产访问、上线、真实付款、未跟踪私钥读取、已有测试数据删除或未经用户同意的临时资源清理。

| ID | 对应需求 | 可观察结果 |
| --- | --- | --- |
| AC1 | R1 | 合法开发者密钥可以创建允许购买的订单；非法凭证、停用商户及跨商户套餐不可下单。 |
| AC2 | R2、R5 | 未支付或 paid 未 fulfilled 时不能领取；完成交付后有独立订阅 Key；重复通知、领取和恢复不重复授予或无故换钥。 |
| AC3 | R3 | **只携带订阅 Key、不带商户密钥或 Cookie** 即可查询对应订阅、当期额度及正常 Coding API Key；周期重置与正常额度统计一致。 |
| AC4 | R4 | 订阅 Key 无法通过 Coding 鉴权；不能用参数扩权读其他订阅；其他用途 Key 无法通过新查询接口鉴权；错误不泄露敏感材料。 |
| AC5 | R1 | 原有订单、账户 Key 获取、商户额度、收银台及托管 H5 契约保持兼容，推理计费不变。 |
| AC6 | R6 | 秘密只经允许的鉴权头/专用敏感响应传输；响应不可缓存，日志不含原始凭证；新额度输出在 2^53 及 int64 边界仍精确。 |
| AC7 | R7 | 仅订单所属商户在 paid + fulfilled 后可领取；跨商户不可领取；公共收银台及 H5 始终不含订阅 Key。 |
| AC8 | R8 | 同一份订阅续费后原 Key 查询到更新的有效期与额度；不会绑定到其他订阅；未作明确重置则不换钥。 |
| AC9 | R9 | 到期后可读该订阅到期状态和历史统计，但响应不含 api_key；他份有效订阅不能为此 Key 放行取钥；历史余额不是当前可用额度。 |
| AC10 | R10 | 所属商户可重置；提交后新 Key 可查、旧 Key 的新请求失败，Coding API Key 与订阅权益不变；跨商户或用订阅 Key 不能重置。 |
| AC11 | R5、R6、R10 | 并发交付/领取/轮换、网络重试、慢请求及锁等待不绕过当前密钥/有效期；失败保持可信支付事实，轮换幂等且不复活旧 Key。 |
| AC12 | R11 | 平台配置后，商户只能列出和创建其已获允许的套餐订单；直接伪造其他 plan_id 也被后端拒绝，已有商户隔离不退化。 |

## 验证与交付限制

- 仅运行本次必要测试：Key 签发/领取/查询/续费/到期/重置、相关支付交付回归和 PostgreSQL 迁移/关键并发。未改前端、计费或其他业务时不跑对应全量测试。
- 数据库只验证 PostgreSQL（pq），不跑 SQLite/MySQL/FoundRows；必要 HTTP fixture 也用隔离 PostgreSQL，不借相关旧用例隐式启动 SQLite。保留现有代码的跨数据库兼容性，不因本次只验证 pq 删除其他驱动支持。
- Go runner 和 DB runtime 仍使用本任务专属 Docker；迁移须有真实隔离 PostgreSQL 证据。
- 编译、静态检查不能代替必要 runtime 验证；确切报告本次未验证项与环境阻塞，不声称未跑的全量测试通过，也不把无关全量测试未执行当成本次新增阻塞。
- 相关 Trellis 规划、后续规范及实现按范围提交 Git；不覆盖用户既有文档修改或加入私钥。npm/pnpm 缓存与诊断记录继续保持 Git 忽略。

## 待确认产品范围

商户可订阅套餐的授权粒度：
